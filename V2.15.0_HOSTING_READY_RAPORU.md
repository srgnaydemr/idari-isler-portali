# V2.15.0 Hosting Ready Son Kontrol Raporu

## 1. Tespit edilen hatalar

- Araç QR / KM backend'i ikame aracı yalnızca `is_active` üzerinden kontrol ediyor, `is_replacement=0` zorunluluğu uygulamıyordu.
- Tekli/toplu QR, QR detay/yazdırma, QR görseli ve public token/KM endpoint'lerinde ikame aracı katmanlar arası engelleyen ortak politika yoktu.
- Daha önce yanlışlıkla açılmış ikame QR kayıtlarını otomatik pasifleştiren migration yoktu.
- İkame türetilmiş araç kaydı bazı akışlarda `ACTIVE` durumuna dönebiliyordu.
- MySQL restore ve SQLite→MySQL migration scriptlerinde eski `2.14.0` şema/sürüm işareti kalmıştı.
- `/arac-zimmetleri/gecmis` bağlantısı vardı fakat gerçek route eksikti ve 404 riski oluşturuyordu.
- MySQL trigger üretiminde legacy SQLite `||` birleştirme ifadesi bulunuyordu; session modu nedeniyle çalışabilse de şema üretimini gereksiz SQL-mode bağımlılığına sokuyordu.
- Yeni attachment oluşturulurken fiziksel dosya yazımı veya versiyon insert'i başarısız olursa boş/yarım DB kaydı kalma riski vardı.
- İlk kullanıcı kurulumu eşzamanlı iki istekte atomik değildi.
- `.gitignore`, `.env.production` gibi tüm `.env*` varyantlarını genel olarak engellemiyordu.
- `package-lock.json` kök sürüm bilgisi yeni proje sürümüyle eşleşmiyordu.

## 5. Halen dikkat edilmesi gereken noktalar

Bu çalışma ortamında npm registry bağlantısı kurulamadığı için `npm ci` tamamlanamadı; dolayısıyla gerçek **`next build`** ve canlı MySQL acceptance testleri burada çalıştırılamadı. Bu durum raporda gizlenmemiştir.

Canlıya almadan önce Node 24 + gerçek MySQL environment üzerinde aşağıdaki üç komutun başarılı olması son zorunlu doğrulamadır:

```bash
npm ci
npm run preflight
npm run build
```

Ardından `npm test` gerçek test veritabanında rollback'li kabul testlerini çalıştırmalıdır. Production veritabanı üzerinde test fixture çalıştırılmamalıdır.

Hosting ephemeral filesystem kullanıyorsa `PORTAL_DATA_DIR` kalıcı volume'a bağlanmadan dosya yüklemeleri production'a alınmamalıdır.
